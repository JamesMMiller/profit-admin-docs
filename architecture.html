C4 diagrams

Start at the estate, then zoom into Profit Admin. C4 here means Context (people and other systems), Container (running pieces), then Component (the important parts inside one piece). Read the caption under each picture before the boxes.

The estate is the shop plus the back office. Profit Admin is one box: it reads money and writes decisions. It does not serve the storefront or hide the CJ tracking key — that is track-proxy.

Access only answers “may this email reach the app?”. Membership in an organisation still comes from Profit Admin itself. Agents never log in as a human — they use an API key from the desk API page.

2. Containers — the running pieces

flowchart TB

  subgraph cloudflare [Cloudflare]

    d1[("D1\nusers, orgs, keys, decisions")]
    hub["DeskHub\nlive clock pings"]
    engine["Engine\nPython FastAPI, P and L"]
    disk[("Org files\nsnapshots and caches")]
  end
  operator --> desk --> worker
  worker --> d1
  worker --> hub
  worker --> engine
  engine --> disk

The Worker is the front door. D1 is durable (it survives a Container sleep). Engine disk is not — that is why decisions moved off markdown files. P&L still lives in Python. Do not reimplement it in the Worker.

3. Components — inside the gateway

flowchart LR
  subgraph worker [Gateway Worker]
    gate["Human gate\nemail session"]
    tenancy["Tenancy\norg, role, billing"]
    keys["Machine keys\nOAuth and pa_live_"]
    decisions["Decision store\nlist and upsert"]
    proxy["Engine proxy\nP and L and refresh"]
  end
  d1[("D1\nenvironment plus org")]
  engine["Engine\nPDF render"]
  gate --> tenancy --> d1
  keys --> tenancy
  decisions --> d1
  decisions -->|"pack JSON"| engine
  proxy --> engine

When you click PDF, the Worker loads rows from D1 and asks the engine to draw the file. Staging and production share one D1 database today; each row carries an environment so they do not overwrite each other.

3b. Components — inside the engine

flowchart LR
  subgraph engine [Python engine]
    collect["Collectors\nShopify, Meta, CJ"]
    pnl["pnl.py\nthe only P and L"]
    snap["Snapshots\nlatest.json and clocks"]
    render["Render\nPDF and Markdown"]
  end
  disk[("Org files")]
  collect --> snap
  pnl --> snap
  render --> snap
  snap --> disk

Refresh and webhooks update the snapshot. The desk polls clocks and reloads when numbers change. Ads Insights default to the whole ad account; optional split overlays campaign / ad set / ad. Improve jobs and DSers spreadsheet watches stay on the laptop — they are not in this Container.
