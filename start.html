What this estate is

Our Tech Accessories is a UK-only Shopify shop (ourtechaccessories.com). It sells everyday tech accessories (chargers, MagSafe banks, mounts, cases). There is no high-street stock. A partner packs the box — mostly CJ Dropshipping, with leftover AliExpress / DSers fulfilments. James is still the merchant: the card charge, the brand, and “where is my order?” sit here.

The public face is three things: the storefront, hello@ourtechaccessories.com, and /pages/track. Profit Admin, Meta Ads Manager, supplier consoles, and this git workspace are operator surfaces. Customers never log into those.

Hosted desk — Ads

Ads (Performance and Intra-day) defaults to the whole Meta ad account. Split by campaign, ad set, or ad overlays that level on the same totals. Views, named subsets, SKUs, and object pickers live under Advanced — they are not the first screen.

Empty object ids on Insights means account-level. The same rule applies to the machine API split field (campaign / adset / ad).

Hosted desk — Mail

Mail shows the store inbox for an owned address such as hello@ourtechaccessories.com. Genuine customer mail that still needs a reply is listed first. Filters include Assist drafts and Needs you. Assist is two-tier triage: a cheap path drafts pitch, FAQ, and volume-deal replies from mail_seeds/; a tool-using agent drafts tracking replies from Shopify and track-proxy facts; refunds, returns, and damage escalate with no draft by default. Mail → Assist has presets (safe drafts, auto cheap, human only, paused), per-category action chips, and an effective-routing summary (auto-send needs an explicit master switch; refund never auto-sends). You still send through the Gmail API (POST /api/mail/send) unless a category is set to auto-send. Cron polls POST /api/mail/triage/poll. A saved reply can also be added with POST /api/v1/mail-drafts. Edit a template under Mail → Templates (built-ins save as an org override with the same id). The mailbox is still Gmail (ImprovMX forwards hello@). After a week of desk drafts you send, run Apps Script disableInboxBot; fulfilment “on its way” mail goes track-proxy → Profit Admin (/webhooks/fulfillment-mail). The Gmail OAuth row lives in D1 (integration_secrets) so a Container replace does not drop the mailbox connection. Empty saves never clear the refresh token or owned addresses; only Disconnect deletes the row.

How a sale becomes a desk number

  1. Meta (or organic) lands on a locked PDP handle. Do not rename live campaign URLs; hot-swap the product under the handle.
  2. Shopify checkout. Payments Basic UK — the desk assumes 1.5% + £0.25.
  3. Fulfilment: CJ app or leftover DSers. Tracking lands on the Shopify fulfilment; track-proxy HMAC-verifies the webhook, caches CJ, and can fire branded “on its way” mail.
  4. Profit Admin collectors pull Shopify orders, Meta Insights, and landed COGS (DSers ledger → CJ API → Shopify unitCost). pnl.py is the only formula.
  5. Hosted: Shopify webhooks bump the orders clock; a 15-minute cron bumps the ads clock and a short tracking batch for Delivery times. The desk polls clocks and reloads. Full Refresh still owns CJ freight and catalog.

Meta has no spend webhook — Ads can lag 15 minutes. A new webhook order may sit on unitCost until the next full Refresh quotes freight. Never invent cost on a Worker-only path.

Finance on the desk is that same P&L, summed for a period (all time, this month, last 7 days, last 30 days) against the matching prior window. It is a management view, not a tax computation. Bank readings, and any large debtor or creditor, are figures an owner types in. A reading can be removed, and it can store the all-time profit beside the balance. There is no bank feed. Customers pay at checkout, so the desk does not keep an aged debtor ledger.

Invariants

P&L is Python. apps/profit-admin/pnl.py is the only formula. Do not reimplement contribution, MER, or ROAS in Worker JS.
Decisions are D1. POST /api/v1/decisions only. Do not prepend MASTER_CONTEXT.md. Staging and production share one D1; rows carry environment.
Access ≠ tenancy. Access is the human gate. No D1 membership → Under construction. Agents never use Access cookies; they use OAuth pa_live_… against /api/v1.
Default agent env is production for live Our Tech ops. Staging only while developing the desk. After a material desk write, commit and push profit-admin then business-ops. If the public briefing is now wrong, update site/ and run ./scripts/publish-docs.sh.
Campaign URLs are locked. Live ad landings keep their handle. Fulfilment changes move the product under that handle.
Meta ads stay PAUSED when created from the repo. James unpauses in Ads Manager. Default video for IG + Facebook feed is 1:1.
Shopify webhooks bypass Access. HMAC only (X-Shopify-Hmac-Sha256). Same idea on track-proxy fulfilments.
These do not run in the Container: Improve / Cursor jobs (business-ops cwd), DSers .xlsx watch, Apps Script, theme paste.

Trust boundary on the desk

Humans: Access JWT (Google) or break-glass /gate?t=. The Worker sets X-Profit-Admin-Email, Role, Org. With TRUST_GATEWAY=1 the engine refuses requests that lack those headers (except public paths). Viewer POST to Refresh / Settings is 403.

Machines: POST /api/v1/oauth/token then Bearer access token (or long-lived pa_live_… for scripts). OpenAPI is at $BASE/docs. CLOUDFLARE_API_TOKEN is Wrangler / Access admin only — never the desk Bearer.
